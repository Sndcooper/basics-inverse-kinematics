# Connecting Jupyter & Gait Simulation

This directory focuses on the high-level control logic, specifically gait generation and communicating with the physical robot via Serial (USB/Bluetooth). It bridges the gap between Python simulations (often explored in Jupyter) and the real hardware.

## Key Files

### Gait Generation & Control
- **`gait_sim.py`**: A comprehensive script that runs a phase-based tripod gait.
    - **Features**: Generates smooth parabolic swing trajectories, controls body velocity, and handles the tripod gait logic (moving legs 0,2,4 and 1,3,5 alternately).
    - **Hardware Interface**: Sends computed servo microseconds directly to the robot via Serial (default `COM17`).
    - **Simulation**: Simultaneously visualizes the gait in a 3D Matplotlib plot.
- **`GAIT_Hexapodwalking`**: Likely a data file or a script describing the gait sequence or parameters.
- **`update_gait_cell.py`**: Helper script for updating gait parameters or logic, possibly used within a notebook workflow.

### Testing & Calibration
- **`servo_test.py`**: A utility script to test individual servos or specific movements to verify hardware connections and calibration.
- **`one leg test.ipynb`**: A generic notebook for testing single-leg movements and IK logic before applying it to the full robot.
- **`plot_cords.py`**: A tool to visualize coordinate data, likely used to debug the trajectories generated by the gait engine.

## Usage

**Running the Gait Simulation:**
To control the robot (or just view the simulation), run:
```bash
python gait_sim.py
```
*Note: Check the `PORT` variable in the script (default `COM17`) to match your robot's connection.*
